AT&T Enterprise Systems mTLS via Integration layer

Bottom row under the VTEX stack. SSO and DataLake are in the left column as direct links.

IF-E3 mTLS

AT&T OSS

VTEX: Orders (Checkout) · Inventory · Pricing · Promotions — AT&T's existing OMS/commerce stack remains system of record; VTEX integrates alongside it, not replacing it

POST → Create / update order ← Notification: issuing credits in the wallet ← Notification: retrieving credits in the wallet POST → Inventory reservation ← Status ACK / stock master Confirmed Aug 6: the net credit balance is computed by an external engine that aggregates multiple AT&T sources (loyalty milestones, plan sign-up bonuses, trade-in value, etc.) — VTEX only stores/applies the balance at checkout. End-to-end flow validated in a POC.

Glossary

IF-xx tag
Interface ID on the diagram; full VTEX mapping and calls are in the sections below.
mTLS
Mutual TLS on partner and enterprise integrations through the Integration layer.
Issuing a device
Device Protection pre-bind + Quotation and Price (Asurion).
Seller portal
MVP onboarding/orders for 3P sellers. Confirmed Aug 6: VTEX provides no seller network — AT&T sources, reviews and accepts each seller directly (e.g. Samsung, Motorola); pricing/inventory/fulfillment stay with the seller.
DataLake direct
Left-column event path without Integration layer (IF-E8), same pattern as SSO. Confirmed Aug 6: feeds AT&T's Snowflake instance via the VTEX Data Pipeline product (paid add-on, no VTEX-side egress charge).
AT&T SSO direct
Left-column identity for Deep link / SSO connected to VTEX (IF-E1), not through the Integration layer.
VTEX CDN scope
CDN sits only above the VTEX Account stack (channels → core), not over external / side systems.
